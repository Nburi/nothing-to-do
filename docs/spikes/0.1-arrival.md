# Spike 0.1 · iOS arrival trigger

Refactor plan step 0.1 (R2; risks F1, C1, C10). Server side built 2026-11-06 on
`feature/arrival-spike`. **The real test needs Niels' iPhone** (TESTBERICHT C2).

**Question:** when Niels comes home and the iPhone joins the home Wi-Fi, does a nudge arrive on its
own, before he picks up the phone?
**Success:** 5 of 5 evenings without tapping anything.
**If it fails:** step 3.3 ships only the time-based nudge from the week plan (fallback in R2).

## How it works

```
iPhone joins home Wi-Fi
  → Shortcuts automation runs "Get contents of URL"
  → POST https://<dev-server>/api/arrival   (Authorization: Bearer <arrival token>)
  → server sends a Web Push to every device with notifications on
  → "Du bist zuhause · Zehn Minuten zurücksetzen, …" on the lock screen
```

- The token can **only** call `POST /api/arrival`. Every other API route and `/mcp` answer 403 for
  it (`RejectNarrowTokens`), so a token copied out of the Shortcut cannot read or change tasks.
  Existing tokens are unchanged.
- At most 6 calls per minute. No "once per evening" rule yet, on purpose: for the test you leave
  and rejoin the Wi-Fi several times. That rule comes in step 3.3.
- Every call is logged (`Arrival ping` in `storage/logs/laravel.log`) with how many devices were
  found and how many pushes were delivered. That tells where a missing nudge got lost.

## Set up (about 10 minutes)

**1. The web app on the iPhone must be installed and allowed to notify.** iOS only delivers web
push to an app on the Home Screen (iOS 16.4 or newer).
1. Open the dev server in Safari, Share → "Zum Home-Bildschirm".
2. Open the app **from the Home Screen icon**, Einstellungen → Mitteilungen → turn them on and allow.
3. Send the test notification from the same settings section. It must arrive before you go on.

**2. Create the token** on the dev server:

```bash
php artisan app:arrival-token <your email>
```

Copy the token it prints; it is shown only once. It appears in the app under
Einstellungen › Shortcuts, API & MCP as "iPhone: Ankunft zuhause · Nur Ankunft melden", where you
can revoke it.

**3. Build the automation** in the Kurzbefehle app (labels can differ slightly between iOS versions):
1. Automation → + (new personal automation) → **WLAN** → choose the home network → **Beim Verbinden**.
2. Choose **Sofort ausführen** and turn **Bei Ausführung benachrichtigen** off. Without this, iOS
   asks for a tap and the test is pointless.
3. Action **Inhalte von URL abrufen**:
   - URL: `https://<dev-server>/api/arrival`
   - Methode: **POST**
   - Header: `Authorization` = `Bearer <token>` and `Accept` = `application/json`
4. Optional while testing: add **Ergebnis anzeigen** after it to see the server's answer
   (`devices`, `delivered`, `message`). Remove it for the real evenings.

**Reading the result**

| What you see | Where it broke |
|---|---|
| No log line | The automation did not run (iOS did not see the Wi-Fi join, or still asks for a tap). |
| Log line, `delivered: 0` | Push delivery (VAPID config, subscription gone). Check the test notification in settings. |
| Log line, `delivered ≥ 1`, nothing on the phone | iOS hid it (Focus mode, notification settings of the web app). |
| `devices: 0` / answer 409 | No push subscription: step 1 again, from the Home Screen icon. |
