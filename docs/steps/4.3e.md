# Step 4.3e: projects and groups in the API and MCP (new model)

Branch `feature/api-mcp-new-model`, based on `refactor/refactor` (4ae57e2). Closes the TODO item "Projects in the API/MCP of
the new model". Step 1.5 had pruned every project and group tool (they spoke the old model, the one on `main`); this puts
projects, stages, steps, groups and note cards back, shaped like the app of steps 4.3 to 4.3c.

## Data and migration

None. No column, no migration. Everything goes through `ProjectEditor` and `NoteEditor`, the same services the pages use, so
the rules (order numbering, "wartet auf" loops, stage of another project, tags following the text) are not written twice.

## What is new

| REST | MCP tool | What |
|---|---|---|
| `GET /projects`, `GET /task-groups` | `list_projects`, `list_task_groups` | What the board card shows: current stage, progress, next two steps (`next_steps`), `more`. Same numbers as the Projekte page (`NextSteps`). |
| `GET /projects/{id}`, `GET /task-groups/{id}` | `get_project`, `get_task_group` | The above plus every step (open and done, stage by stage), the stages with open/done counts, the note cards with tags. |
| `POST /projects`, `PATCH /projects/{id}` | `create_project`, `update_project` | Name only (see "Old fields"). |
| `POST /task-groups`, `PATCH /task-groups/{id}` | `create_task_group`, `update_task_group` | Name, list (`todos`/`tasks`), optional `steps` (titles). |
| `POST /projects/{id}/stages`, `PATCH`/`DELETE /stages/{id}` | `add_project_stage`, `update_project_stage`, `remove_project_stage` | Stages in the order you add them, optional target date. Removing a stage keeps its steps (no stage) and sends its notes back to "Lose". |
| `POST /projects/{id}/steps`, `POST /task-groups/{id}/steps` | `add_project_step`, `add_group_step` | A step is a normal task (`TaskResource`); more fields via `update_task`. |
| `PUT /tasks/{id}/place` | `place_step` | One step to a stage and position (4.3c rules: idempotent, `move.changed`, `move.cleared_waits_on`). |
| `PUT /tasks/{id}/waits-on` | `set_step_waits_on` | "Wartet auf", `null` lets go; loops and other projects are refused. |
| `POST /projects/{id}/notes`, `POST /task-groups/{id}/notes`, `PATCH`/`DELETE /notes/{id}` | `add_note`, `update_note`, `delete_note` | Markdown note cards, `#tags` follow the text, `stage_id` sorts a project card into a stage (null = "Lose"). |

Tasks: `TaskResource` now carries `project_id`, `stage_id`, `group_id` (null while the step is in a project) and `waits_on_id`.
`GET /tasks` and `list_tasks` filter by `project_id`, `stage_id`, `group_id`, `size`, `area_id`.
The task fields since 1.1 (`size`, `hard_deadline`, `soft_deadline`, `area_id`, `is_important`, `first_step`) were already in
`create_task`, `update_task`, the REST task endpoints and `TaskResource` since 1.5; the bulk tools run through them, and a test now pins that.

## Compatibility with the old connector

The tools `main` has keep their name where the idea survives, so a connector that knows them still finds them:
`list_projects`, `get_project`, `create_project`, `update_project`, `list_task_groups`, `get_task_group`,
`create_task_group`, `update_task_group`, `add_group_note`, `update_group_note`, `delete_group_note` (same arguments as before,
`content` still answered next to `body`). The three group-note tools are thin wrappers over `add_note`, `update_note`,
`delete_note`. Nothing was renamed or removed that exists on the base.

Deleting is guarded like `delete_task`: `delete_note` needs the `mcp:delete` ability and the name of the owner as `confirm_name`;
`remove_project_stage` asks for the stage name (it deletes only the stage, but a wrong id would still hurt).

## Old fields

`deadline`, `external_url` and `brainstorm` of a project are not in the new API: the app shows none of them (4.3 decision), the
brainstorm text became note cards (4.3b). They stay in the database and the export. `create_task_group` no longer takes `task_ids`
(moving existing board tasks into a group is #36); the call is refused with a message that says so instead of silently ignoring it.

## Not in this step (waits for open PRs, the base does not have them)

- **Delete** of projects and groups (`delete_project`, `dissolve_task_group` on `main`): the service method comes with PR #36
  (4.3d); adding the tools then is a few lines each (`ProjectEditor::delete…`). Same for moving a board task into a project or
  group and stage order (`moveStage`).
- **`set_task_order`** still writes `sort_order`. The shared board order (`board_position`, PR #39, step 4.8) is not on this base,
  so the tool does not move the board yet. Once #39 is merged it should go through `BoardOrder`; for project steps `place_step` is
  the right call already.
- `note_to_step` ("→ Schritt") and moving a note by position are not exposed.
