# Step 1.8 · Review of phase 1

Refactor plan step 1.8. Done 2026-11-09 on `feature/phase1-review`, stacked on 1.5 (PR #12). Phase 1 is
"everything that decides without showing a pixel", so the review checks the engines, not screens.

## How it was reviewed

1. **Code review** of the whole phase-1 stack (`refactor/refactor...feature/capture-api`), high effort:
   six findings, all fixed on this branch (table below).
2. **Flow test** `tests/Feature/Refactor/EveningFlowTest.php`: one user, one week, every engine in the
   order the evening loop will use them (week plan → capture and sort → no suggestion before the block →
   low battery warm-up → session with Done inside it, break, carry-over → early warning → drop → soft slip
   → paused day). **It found a real bug in the spike-0.2 engine** (below).
3. **Requirement check** against REQUIREMENTS.md (table below).
4. **Migration rehearsal on a copy** of the local dev database with every phase-1 migration that dev did
   not have yet: `migrate` and `migrate:rollback`, each compared with `app:rehearsal-compare`:
   **"Nothing lost"** both ways (43 tables, 521 rows; 3 new tables, 2 new columns). The copy and the
   snapshot files were deleted afterwards; the real dev database was not touched.
   The rehearsal on a **production** copy still needs the dump (0.3, TESTBERICHT C3).

## Fixed

| Where | What was wrong | Found by |
|---|---|---|
| `DeadlineFeasibility::check()` | With more hard work than fits, the second pass (hard work as late as possible, meant to let soft work slip) could also make an **earlier hard deadline late** that the first pass met. The warning then named the wrong task and day. Pass 2 is now only used if it adds no late hard task. | flow test |
| `app:run-planning-checks` | A warning stayed on **forever** once the user had no open work left (only users with open work were checked). | code review |
| `WeekPlanEditor::moveOccurrence()` | Moving from a day the block is not on wrote a stray tombstone and **invented a one-off**. Now refused with a message. | code review |
| `Suggestions::another()` | Read the whole plan three times per tap; now once. | code review |
| `Suggestions` evening row | Two devices writing the first battery / Another of an evening at once could get a 500 from the unique index. The loser now reads the winner's row. | code review |
| `AreaController`, `PlanningController` | A ternary with equal branches, a missing type. | code review |

Noticed on the way, not fixed: the **service worker serves a stale copy of a page on navigation** even after
the page changed on the server (a fresh `fetch` got the new HTML, the navigation the old one, until the URL
changed). For a deploy that means users can see an old page until the cache turns over. Worth a look in 2.2,
when the shell and its service worker are rebuilt.
