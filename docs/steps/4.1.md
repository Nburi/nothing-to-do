## Rules worth knowing

- **Zeitplan.** A new block asks "Nur am Di 17.11." / "Jeden Dienstag" (one day) or "Nur diese Woche" / "Jede Woche"
  (several days): this week = one one-off per date, every week = one repeating block on those weekdays. A block of the
  Wochenplan asks the same when changed or removed; moved to another day "Jede Woche" moves that weekday in the Wochenplan.
  A one-off has no question. "Zurück zum Wochenplan" undoes a one-week change; a block moved to another day this
  week only has it too ("Diese Woche verschoben, von Mi 2.12."): the one-off and the tombstone on the old date go,
  the date follows the Wochenplan again, "Rückgängig" brings the move back. It is offered only while the
  tombstone is there and the block still repeats on that weekday.
- **Wochenplan.** No question: every change is every week from tomorrow, days changed on their own stay (rule of 1.2).
  "Aus dem Wochenplan entfernen" stops the block; past weeks stay.
- **Pauses.** Calendar range in two taps (a single tap and "Pausieren" pauses one day), optional note. A click on a day
  header (desktop) or "Mo pausieren" (phone) switches one day off or back on. Pauses hide repeating blocks, never one-offs.
  A paused day is marked on its header only (hatch, "Pause · note"; on the phone the day strip tab); the column stays plain.
- **Sessions** in the day headers and blocks come from the engine's `SlotCalculator`, the same numbers as suggestion and
  early warning. The Wochenplan's numbers are the template alone (no pauses, no one-week changes).
- **Undo** is offered after every change, never a confirm. A category deleted in the settings keeps its blocks (stored
  name and colour) and stops being work time.
- **4.2 "Mehr Zeit"** writes a one-off through `addOnce`; the editor shows it as a block on that date and can remove it.

## Decisions I made (please check)

1. **Soft delete only from the new settings.** API, MCP and the old settings still hard-delete a category, so their
   documented behaviour (and tests) stay. Soft-deleted categories are never purged.
2. **Undo journal in the page.** The undo of the last edit lives in the page (locked Livewire state); reloading the page
   drops it. Undo restores deleted rows with their old id when it is still free.
3. **A long press on the phone** also moves a block (vertically, on the shown day). Moving to another day on the phone is
   the "Tag" field in the form.
4. **A short tap on the phone** opens a one-hour block from the tapped time (your pick); a mouse click does the same.
5. **Blocks before 07:00** scroll the grid up to the earliest block; otherwise it opens at 07:00.
6. **Termin names** of the Wochenplan are edited in the Wochenplan; in the Zeitplan the name field of such a block is read-only.
7. **FUNCTIONS.md** does not exist on `refactor/refactor`; the feature is documented here instead of creating it in
   parallel with the sibling steps.

8. **Moved blocks remember their origin** (2026-11-23). Blocks moved before `moved_from_id` existed have no tie and
   are not guessed at: a look-alike block (same category, same length) is not proof, and a wrong guess would delete
   a block. Resetting a moved block removes the tasks and values bound to that block, like "Zurück zum
   Wochenplan" for a changed block does; "Rückgängig" restores them.

## Ghosts of paused days (B6, Niels' decision 2026-11-24)

Niels: the ghosts should be "very quiet, I would simply make them very pale". Branch `feature/pause-ghosts`.

| Piece | What |
|---|---|
| `WeekPlan::ghostsOn($date)` | On a paused date: the template blocks it would have had, one-week changes applied, cancelled ones gone, brought-back ones removed. Empty on any other date. `blocksOn()` is unchanged for paused dates, so ghosts never reach capacity, forecast, the pick engine or a session start (R4 guarantee kept, test `PauseGhostTest`). |
| `WeekPlanReader::ghosts()` | The same per date range, for the editor only. |
| `WeekPlanEditor::restoreGhost()` | Brings one ghost back **for that date only**. It takes no `ChangeScope`: restoring is by definition an exception for one day; the series, the pause and the other ghosts stay. |
| `schedule_events.pause_exception` | Additive boolean, default false (migration `2026_11_24_000001`, no data touched). A brought-back ghost is the occurrence's own row marked as an exception to the pause: it shows once, also after the day is switched back on (no duplicate), keeps a one-week change, and `ScheduleEvent::scopeVisible()` lets it through so the old screens agree. |
| `OneOffChange::$pauseException` | How the engine learns about it; the block counts as "changed this week" (dashed, "Zurück zum Wochenplan" in its form). |
| View | `data-pause-ghost` buttons in the paused column, `week.ghost.*` copy (de/en). Same markup on the phone's one-day grid. A click or Enter brings it back (`Week::restoreGhost`), undo through `WeekPlanJournal` like every other edit (the row update is journalled). |

**Look.** Text 45 % ink on the surface (`Theme::GHOST_TEXT_WEIGHT`), fill 6 % of the category colour (Termine: the deep tone), a hairline of 16 %, no hatching, no animation; a dotted "Zurückholen" appears only on hover or focus on blocks of 90 minutes and more. Name and action are in the button's `aria-label`.

**Contrast.** Ghosts are **excluded on purpose** from the 4.5:1 rule of `ThemeContrastTest` (stated in that file). A separate test keeps a floor: ghost text must stay at least 2.5:1 and below 4.5:1 on the surface in every theme, light and dark (measured 2.66 to 4.14 at 45 %).

**Rules worth knowing**
- Only the Zeitplan has ghosts. The Wochenplan has no pauses, so no ghosts.
- Removing a brought-back block "this week only" cancels that date (no ghost afterwards); "Zurück zum Wochenplan" (or undo) turns it into a ghost again.
- A repeating block that was re-categorised for that date only, and a row of a series that stopped repeating on that weekday, leave no ghost (the old rule hides them too).
- Restoring on a date that is not paused, outside the shown week, or of another user's block creates nothing.
- Decision I made: a tap on a ghost brings it back at once (no confirm), because undo is offered. C62 asks whether that is too easy to hit on the phone.

## Colours for Termine (Niels, 2026-11-24)

Niels: "for Termine I would also like the colour choice". Branch `feature/termin-colors`, stacked on `feature/pause-ghosts`.

| Piece | What |
|---|---|
| Palette | The five keys of the categories, `ScheduleEvent::EVENT_COLORS` (Ocker, Magenta, Grün, Rot, Tinte): a key, never a free hex, so every theme (seven, light and dark) supplies the colour (`--color-<key>` in `app.css`). Names come from `week.colors.*`, the same strings the category settings use. |
| `x-shell.color-picker` | New small component: one radio group of swatches, optional first swatch "Standard". Used in the block form. The category settings keep their own popover (a different wrapper around the same palette). |
| `termin_color` | Additive nullable string on `schedule_events` **and** `event_templates` (migration `2026_11_24_000002`, nothing backfilled). null = "Standard" = the current dark Termin block, so every existing Termin looks unchanged. |
| Why a new column | `color` is NOT NULL with default `'contour'`: an untouched Termin and one that deliberately got Ocker cannot be told apart, and showing `color` would have turned every existing dark Termin ochre. `color` stays what it was (old screens, API and MCP read it); the editor writes both. |
| `HasTerminColor` | A `saving` hook on both models copies an explicit `color` of a category-less row into `termin_color` unless the writer set `termin_color` itself. So a colour set through the API, MCP or the old forms shows in the grid too. A category block and an occurrence row of a series never copy. |
| Engine | `Template`, `OneOffBlock` and `Block` carry `tint` (editor only; the engine ignores it). |
| `WeekPlanEditor` | `addRepeating`, `addOnce`, `updateOnce`, `updateTemplate` already took `$color` (validated against the palette); they now store it as `termin_color` for a Termin and drop it for a category block. "Standard" keeps the `color` the old screens stored (only a chosen key rewrites it). |
| Look | A coloured Termin is drawn like a category block: 20 % of its colour in the surface, a solid border of the colour, ink text (`Theme::TERMIN_TINT_WEIGHT`; `ThemeContrastTest` checks ink on every key in all themes). "Standard" stays the dark block. Ghosts and the Wochenplan side list use the colour too. |
| API / MCP | No new field: `color` is already optional there and now reaches the grid through the hook. `termin_color` is not exposed (it is the editor's view of `color`). |

**Rules worth knowing**
- An occurrence of a repeating Termin takes its colour from the series, like its name: the picker is greyed out in the Zeitplan ("Die Farbe kommt aus dem Wochenplan") and edited in the Wochenplan. Moving it to another weekday "every week" keeps the series colour.
- Turning a Termin into a category block drops its colour; the category's colour is used.
- Undo restores the old colour (the journal records the row update).
- Decision I made: Termin blocks in "Tinte" and "Standard" look alike in themes where ink is close to the deep tone, so "Standard" is a hollow ring in the picker (C66 asks whether that is clear).
