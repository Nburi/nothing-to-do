# Step 5.1 · Onboarding, empty states, German and English
Refactor plan step 5.1 (phase 5, release; serves R7 "a stranger understands it cold", risk F10). Built 2026-11-26 on
`feature/onboarding-i18n`, branched from `refactor/refactor` (no dependency on the open PRs #36–#43).

## What changed
- **Language per user.** `users.locale` (`de` default, `en`). Middleware `SetUserLocale` (web group, so Livewire updates
  too) applies it with `Locales::apply()`: translations, validation messages, Carbon day and month names. The card
  "Sprache" in the shell settings (`Shell\LanguagePicker`) saves it and reloads the page, so layout and every card come
  back in the new language together. A damaged value falls back to German (`Locales::for()`).
- **Pushes in the user's language.** The evening nudge and the crunch warning are built inside `Locales::within($user, …)`,
  because the scheduler runs in the app default.
- **Error pages** (404, 4xx, 5xx, maintenance) read from `lang/*/errors.php` and carry the right `lang` attribute.
- **Dates** (`App\Support\Dates`, `lang/*/dates.php`): the short dates, stage dates and the review header follow the language.
- **`WeekReview`** no longer pins day names to German (`locale('de')` → the user's locale).
- **Lang files:** the shell was already almost fully on `lang/`; what was left were the error pages and the new strings
  (`lang/*/onboarding.php`, `lang/*/errors.php`). German `validation.php` got the two keys Laravel added (`array_keys`,
  `base64`).
- **Parity test** `tests/Unit/LangParityTest.php`: same files and keys in `de` and `en`, same `:placeholders`, every key
  that Blade or PHP asks for (`__()`, `trans_choice()`, `@lang`) exists in both languages, and the German copies of
  Laravel's own `auth`, `passwords`, `validation` match the framework's keys (English for those comes from the framework).
  Checked that it bites (a key in one language only, and a key the code uses but nobody wrote, both fail).
- **First-run tour** (`Shell\Tour`, mounted in the shell layout, so a new account sees it on whatever page of the new
  app it opens first). Three taps: capture → sort → evening start with the board folding away. Esc, "Überspringen" and
  "Los geht's" are the same exit; arrow keys move; Tab stays inside; under reduced motion nothing animates (the pictures
  are static). Step changes are client-side (Alpine, no server round trip); only the end calls `finish()`.
- **State per user:** `users.shell_tour_seen_at`. Re-openable from the settings card "Rundgang" (link to
  `/board?tour=1`; the parameter is removed from the address bar when the tour closes). A replay does not move the date of
  the first time.
- **Empty states and clipping (B1, B2):** see "Visual check" below.

## Migration (additive, nothing dropped)
`2026_11_26_000001_add_locale_and_shell_tour_to_users_table`: adds `locale` (default `de`) and `shell_tour_seen_at`
(nullable) and **stamps every existing user as having seen the tour**. Existing users are therefore never pushed through
it; only accounts created afterwards start with `null`. `down()` drops both columns. Tested by running `down()` and `up()`
on a table with users.

## Decisions for Niels (please check)
1. **Existing users do not get the tour on their own.** They are stamped as "seen" by the migration and can open it from
   Einstellungen → Rundgang. At the switch (5.4) you may want everybody to see it once: that is one line,
   `UPDATE users SET shell_tour_seen_at = NULL`, run with the release. Not done here because it would show a tour on
   the dev server to every tester.
2. **The tour lives in the new app only.** New registrations still land in the old app (`defaultLandingRouteName()` is
   `app` until 5.4) and see the tour the first time they open `/board`. The old tutorial (`/app/onboarding`, quiz,
   list concepts, modules) is untouched and still runs after registration; it describes the old app, so **5.4 retires it**
   together with `/app`. I did not delete it: it works, and the switch decides what registration redirects to.
3. **Overlay, not a page.** A calm dialog over whatever page the account opened (bottom sheet on the phone, centred card on
   the desktop), dimmed, no progress bar, three dots. Pictures are small token-built sketches, no illustration assets.
4. **Copy stays generic.** The three texts name only the Inbox, the daily sort, "Start" and the folding board: nothing from the
   To-do session, shared order or pause ghosts (open PRs). If those change what "Start" or the sort card says, the tour text
   is three keys per language in `lang/*/onboarding.php`.
5. **English dates:** day first with the month as a word ("25 Nov", "Wednesday, 25 November"), so nobody has to guess
   between 3/4 and 4/3. German keeps "25.11.". The patterns are in `lang/*/dates.php`, used through `App\Support\Dates`
   (found in the browser: the English review still said "25. November"). There are no hand-formatted numbers in the
   shell; times stay 24 h in both languages (the week plan is built on `HH:MM`).
6. **The API answers stay German** (`/api/capture`, `/api/arrival`: messages for the Shortcut). They run without a web
   session; making them follow `users.locale` is a small follow-up if you want it.
7. **Not translated (old app, retired in 5.4):** everything under `/app/*`, the welcome-back lines in `User`, the old
   `Services/*` copy (DayPreviewData, HeaderBadges, ProgressStats, …). The parity test only covers keys in `lang/`.
8. **Test factory:** `UserFactory` now creates users with `shell_tour_seen_at` set, so the tour overlay never lands on an
   unrelated page test (also for the other open PRs). `User::factory()->unseenTour()` is a brand-new account.

## Heads-up for the other open PRs
A test that sets the language with `app()->setLocale('en')` and then calls a page as a user now sees German: the
middleware applies the user's language on every request. Use `User::factory()->create(['locale' => 'en'])` instead (as
`SundayReviewPageTest::test_it_speaks_english` now does). New user-facing strings go into `lang/de` and `lang/en`;
`LangParityTest` fails if one side is missing.
