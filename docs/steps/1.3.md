## The rules

1. **Candidates:** open To-dos and Tasks of the user. Inbox and Later are never suggested as work.
2. **Only inside a pomodoro block** (A19). A fixed appointment cuts the block (E1); where pomodoro blocks
   overlap, the one that started first decides (E2). Outside, the board gets `nextBlockAt` instead.
3. **Area filter:** the running block's category decides (E5). In a session outside blocks the user chose
   to work, so `nextInSession` has no filter there.
4. **Tiers** (always first): 0 = late or has to start today · 1 = has a deadline · 2 = no deadline.
5. **Battery** orders inside the tiers:
   - **Okay:** deadline order (earliest binding deadline, hard before soft, smaller first), then the board order.
   - **Low:** a **warm-up of up to two Quick tasks** first, whatever their tier; then smaller before bigger;
     Long and Block are **shrunk to one session** tonight. Late work is never shrunk.
   - **Good:** bigger before smaller, so the largest deadline work gets the full battery.
6. **Ties** end on the board position (To-dos before Tasks, then manual order) and the id.
7. **Another** skips tonight's pick; the skips are kept on the evening (swap log). When every candidate was
   skipped once, Another starts over at the top instead of running dry.

## Decisions I made (please check)

- **Start-by** is as-late-as-possible planning, not "deadline minus size". It respects area links and the
  sessions really left, so "has to start today" is true, not a guess.
- **"Warm-up rule" = low battery only**, two Quick tasks (the plan artifact's demo and A1). Okay and Good have no warm-up.
- **The evening is the local calendar date.** A battery set at 23:50 is gone at 00:00. Simple; revisit if
  evenings regularly run past midnight (E8 already keeps sessions on the day they started).
- **The read side of the week plan came forward from 1.2.** 1.2 is now the write side: "this week only" vs
  "every week" as an explicit choice, pause ranges and the per-date rules on save.
- **`first_step`** is a new column rather than a parsed notes line; the notes line is only the fallback. It is
  also where the craft ideas' "where to begin" note will land (data migration table).
