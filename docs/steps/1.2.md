Refactor plan step 1.2 (R4; risks C2, C3). Built 2026-11-08, stacked on 1.4 (PR #10). The **read side**
(`WeekPlanReader`: old tables → `App\Planning\WeekPlan`, no materialising) came with 1.3 because the pick

## The rules (same per-date model as the old app)

- **Repeating block** = `EventTemplate`. **This week only** = a `schedule_events` row with the template id for
  that date. **Cancelled** = such a row with `is_cancelled` (tombstone). **Moved to another date** = tombstone
  on the old date + a one-off on the new date.
- **Every week** changes the template from tomorrow on. Future rows that the old screens materialised follow
  the template, **unless the user changed that date on purpose**: a row that no longer matches the old
  template is kept. *The old app overwrote those, which lost one-week edits.* Today and the past are never rewritten.
- **Cancel every week** removes that weekday. With no weekday left the template stops repeating; it is never
  deleted, so its past rows stay as history. *The old app deleted the template and every row with it.*
- **Pauses**: one row per date, ranges up to a year (366 days), a single day can be switched back on. They hide
  template blocks, never one-offs.
- **Blocks**: local "HH:MM", inside one day, at least 10 minutes. Validation messages are German by default.

## How it is tested

- `WeekPlanEditorTest`: every operation, the old-row cases, history, validation, foreign ids.
- **Property-style (risk C3):** 40 seeded random sequences of 12 edits (change, cancel, move, pause, resume,
  materialise like the old screens) on two templates; after each sequence the new reader and the old screens
  must show the same blocks on every one of 21 dates. This test found the pause bug above.
- `WeekPlanReaderTest` (from 1.3) and the engine fixtures A3 / A4 / A5 stay green.

## Decisions I made (please check)

- **"Every week" keeps one-week edits**, and **removing the last weekday stops the series instead of deleting
  it**. Both protect user data and differ from the old app.
- The pause bug is fixed here, on the refactor branch. **It is also live on prod** (`main` has the same scope):
  a paused day still shows an occurrence that was edited in the form. A hotfix for `main` is a one-line change.
