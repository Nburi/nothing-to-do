The export now holds each project's and group's note cards with their tags (`projects[].notes`,
`task_groups[].note_cards`), next to the old `brainstorm` and `notes` (group_notes) fields.

## How it works

- `App\Services\Projects\NoteEditor`: add, edit, place / move to a stage, delete, "→ Schritt", restore
  (undo). Tags follow the text on every save; tags no note uses are removed so the suggestions stay clean.
- `NoteTags`: a tag is `#` + a letter + up to 49 letters, digits, `_`, `-`, not glued to a word, URL or
  entity (`a#b`, `x.ch/#anker`, `#42`, `# Überschrift` are no tags). Lower case.
- `Note::html()`: the app's one safe Markdown renderer (`App\Support\Markdown\Markdown`: raw HTML
  stripped, unsafe links dropped) plus tags marked outside links and code; a click on a tag filters.
- "→ Schritt": title = first line without Markdown marks and tags; the **whole note** is kept as the
  step's notes. Undo removes the step it made (only if still open) and brings the note back.
- UI: `Livewire\Concerns\ManagesNotes` (project and group page), `shell/notes-panel.blade.php`.
  Desktop drag uses SortableJS (`notePile` in `app.js`), grip on the left of each card; the chip sheet
  works on every device (keyboard too). Long notes fold after ~4 lines ("Mehr").

## Decisions Niels should check

1. A tag needs a letter first (`#42` is no tag) and is stored lower case (`#Bug` = `#bug`).
2. The filter works inside one project or group; tags are shared, so the suggestions show all your tags.
3. "→ Schritt" puts new project steps into Tasks (the list select of the step form is not asked again).
4. Long notes fold after about four lines.
5. The old `brainstorm` text and `group_notes` stay in the database untouched (export shows both).
