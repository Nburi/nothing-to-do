# Step 1.7 · Session engine wired to storage

Refactor plan step 1.7 (R1, R9; risks F14, C14). Built 2026-11-08 on top of the merged engine spike
(0.2) with decisions E1–E10 approved. No UI: the session view is step 3.1.

## What changed

| Piece | What |
|---|---|
| `pomodoro_sessions` | New table, one row per user (`user_id` unique, cascade), `state` JSON = `App\Planning\Session\SessionState`. |
| `App\Models\PomodoroSession` | The row; `User::pomodoroSession()`. |
| `App\Services\FocusSession` | `current`, `remainingSeconds`, `start`, `complete`, `pause`, `resume`, `stop`. Every write locks the user's row in a transaction, so two devices tapping at once are applied one after the other. |
| `SessionEngine::stop()` | New: leave the session without Done ("back to the board"). Keeps the day's counter; a stopped session does not count toward the long break (same reasoning as E6). |

## Rules worth knowing

- **Reads never write.** `current()` applies elapsed time in memory only; the stored state moves on the next action. A device away for hours reads Ready, never a run of phantom sessions (engine behaviour).
- **Done completes the task** through `TaskMutator::applyUpdate()`, the same path the REST API and MCP use, so `completed_at` and the other completion side effects stay identical.
- **Done is idempotent:** a task that is not the running one changes neither the session nor the task.
- **Task ids are owner-scoped and must be active.** A foreign, deleted or completed id is a `ModelNotFoundException` before anything is written.
- **Timezone:** users store a UTC offset, not an IANA zone. The engine needs a zone only to decide which local day "today" is (long-break counter, E3/E8), so the offset in force at that moment is passed as a fixed `+HH:MM` zone. Tested around local vs UTC midnight.
- **Fixed rhythm** 25 / 5 / 15 / every fourth (REQUIREMENTS § 3). The old per-user Pomodoro settings belong to the old screens and are not read.

## Not part of this step

- Choosing the next task after Done: the caller passes it; the pick engine is 1.3.
- HTTP, Livewire, API and MCP entry points (3.1 and 1.5).
- The old per-event Pomodoro on `schedule_events` is untouched and keeps serving the old screens until they are retired.
