## How it works

| Piece | What |
|---|---|
| Board stays rendered | In a session the board region is still in the HTML, `inert` and `aria-hidden`, folded and invisible. Livewire's morph keeps its elements, so the server's switch of `data-shell-mode` is a plain CSS transition (risk C5). |
| `body.shell-folding` | Set by Alpine (`shellFold` in app.js) on the click on Start, before the server answers, so the fold moves at once (not under reduced motion: there the board stays until the session is there). Taken off two frames after the answer; if the server said no (task gone), the board unfolds and the notice explains. |
| `body.shell-entering` / `shell-returning` | Only for the moment of a switch: the rail slides in, its counts pop, the drawer rises; on the way back the done row and the next suggestion rise. A reload or a second device shows the session without motion. |
| Card flight (ghost, C1) | On the click a ghost of the session card (`shell/session-ghost.blade.php`, `wire:ignore`, hidden until then) is filled from the started card (`data-fold-title`, `-area`, `-size`, `-start`) and flies from that card to where the session card will stand, in 520 ms. Its content fades in from 40 %, so the title and the full timer stand when the columns are gone, whatever the round trip takes. The server's card stays hidden until the ghost has landed; then the two swap in one frame (a short glide only if the guess was off). Without a click (reload, other device) nothing moves. |
| Fold hooks | `fold-col` (Werkbank columns, `--i` for the order), `fold-pile` (Stapel piles), `fold-away` (top bar, time line, tray labels, + button), `fold-tabs`, `fold-tray`, `fold-card`, `fold-rail`, `fold-rail-count`, `fold-arrive`, `fold-drawer`, `fold-return`; `data-fold-from` on cards that can be started, `data-session-card` on the session card. |
| Starts | From the board (suggestion card, list rows, Stapel sheet in board mode) Start calls `foldInto($el, () => $wire.start(id))`. Starts inside a session (break, peek panel) stay plain `wire:click`. |
| Reduced motion | No transitions, no keyframes, no card flight: the same change, instant (CONVENTIONS 10). |
| A11 | Entry points inside an `inert` region no longer count, so the folded board cannot fake parity in session mode. |

## Tests

`ShellBoardTest`: the board stays rendered but inert in a session, with four folding columns, four
piles, the rail and the drawer; every start from the board folds and knows its card, starts inside
a session do not; the 520 ms and the reduced-motion rule are pinned. `ActionParityTest` ignores
inert entry points.

## Visual check (TESTBERICHT B5)

Real browser (Playwright, 1280 and 390 px), throwaway local account:
- Werkbank: the columns fold one after another while the card holds its place; the card flies to
  the middle; the session stands at about 520 ms; "Session beenden" unfolds the board with the
  next suggestion. Card position stays stable after the flight.
- Stapel: the piles slide down and fade, the server answered after about 150 ms, the card grows
  from 234 to 430 px until about 520 ms.
- Reduced motion: no card animation, columns switch instantly.
- Screens: `docs/screens/3.1-*`.

**Known issue (open question for Niels):** in the Stapel layout in a *desktop* browser with classic
scrollbars (a narrow desktop window), the page gets a scrollbar for about 400 ms during the fold;
the drawer wraps to two lines and the card jumps 20 px when the scrollbar goes. Phones use overlay
scrollbars, so this cannot happen there. Two fixes did not help (`overflow: clip` on the board,
wiping the tab bar with `clip-path`) and were reverted. Next idea: `scrollbar-gutter: stable` on the
shell page.

## Finding C1: "Verzögerung vor dem Timer" (Niels, 2026-11-17)

Niels likes the fold a lot ("gefällt sehr"). But after everything had folded away there was a short,
noticeable wait before the timer came up. The fold itself is unchanged.

**Where the gap came from** (real browser, headless Chrome, 160 tasks, a recorder sampling the painted
state every frame): the session card did not exist before the server had answered, and the choreography
then started from the answer, not from the click. The card's flight began at the answer, and its content
stayed invisible for the first 55 % of "flight + 120 ms". With a quiet machine (answer after ~140 ms) the
columns were gone at ~400 ms, but the timer was only 48 % visible at 520 ms and fully there at ~650 ms.
With a slower answer the gap grew one to one (a busy machine, answer after 1.1 to 1.9 s: the card appeared
1.4 to 2.1 s after the click). The page re-renders about 630 KB of HTML for this board on every answer,
so the answer is never instant.

**Fix:** render the timer as part of the fold. The ghost card above is drawn from the click on, so the
card flies while the columns fold and the timer stands by the end, independent of the answer. The top row
(`fold-arrive`) takes what is left of the fold as its delay (`--fold-arrive-delay`) instead of waiting
320 ms after the answer. Under reduced motion the board now stays until the session is there (before, the
columns vanished at the click and the page was empty until the answer); the change itself stays instant.

**Measured** (1280 × 800 / 390 × 844, median of 3, painted state; "+600 ms" delays the Livewire request in the browser to simulate a slow server):

| | before (answer ~140 ms) | after (answer ~210 ms) | after, +600 ms (answer ~850 ms) |
|---|---|---|---|
| columns gone | 398 ms | 410 / 395 ms | 397 / 397 ms |
| timer ≥ 50 % visible | 529 / 498 ms | 390 / 342 ms | 295 / 297 ms |
| timer ≥ 95 % visible | 647 / 631 ms | 466 / 462 ms | 463 / 462 ms |
| timer visible at 520 ms | 48 / 61 % | 99.6 / 99.6 % | 100 / 99.6 % |
| jump of the timer at the hand-over | 0 / 12 px | 0 / 0 px | 0 / 0 px |

In both layouts the ghost lands where the server's card stands (Werkbank 1280 × 800: 426, 126, 520 × 582; in
Stapel 390 × 844 the hand-over needed no glide either). A task with a first step or a three-line title can differ from the guess; the server's
card then glides the difference in 240 ms. The rail, top row and drawer still arrive with the answer.
