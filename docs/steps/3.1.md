## How it works

| Piece | What |
|---|---|
| Board stays rendered | In a session the board region is still in the HTML, `inert` and `aria-hidden`, folded and invisible. Livewire's morph keeps its elements, so the server's switch of `data-shell-mode` is a plain CSS transition (risk C5). |
| `body.shell-folding` | Set by Alpine (`shellFold` in app.js) on the click on Start, before the server answers, so the fold moves at once. Taken off two frames after the answer; if the server said no (task gone), the board unfolds and the notice explains. |
| `body.shell-entering` / `shell-returning` | Only for the moment of a switch: the rail slides in, its counts pop, the drawer rises; on the way back the done row and the next suggestion rise. A reload or a second device shows the session without motion. |
| Card flight (FLIP) | The started card's place is remembered on the click; the session card grows out of it (Web Animations API). It takes what is left of the 520 ms, at least 260 ms. Its content fades in once it has landed, so text never stretches. |
| Fold hooks | `fold-col` (Werkbank columns, `--i` for the order), `fold-pile` (Stapel piles), `fold-away` (top bar, time line, tray labels, + button), `fold-tabs`, `fold-tray`, `fold-card`, `fold-rail`, `fold-rail-count`, `fold-arrive`, `fold-drawer`, `fold-return`; `data-fold-from` on cards that can be started, `data-session-card` on the session card. |
| Starts | From the board (suggestion card, list rows, Stapel sheet in board mode) Start calls `foldInto($el, () => $wire.start(id))`. Starts inside a session (break, peek panel) stay plain `wire:click`. |
| Reduced motion | No transitions, no keyframes, no card flight: the same change, instant (CONVENTIONS 10). |
| A11 | Entry points inside an `inert` region no longer count, so the folded board cannot fake parity in session mode. |

## Tests

`ShellBoardTest`: the board stays rendered but inert in a session, with four folding columns, four
piles, the rail and the drawer; every start from the board folds and knows its card, starts inside
a session do not; the 520 ms and the reduced-motion rule are pinned. `ActionParityTest` ignores
inert entry points.

## Visual check (TESTBERICHT B5)

Real browser (Playwright, 1280 and 390 px), throwaway local account:
- Werkbank: the columns fold one after another while the card holds its place; the card flies to
  the middle; the session stands at about 520 ms; "Session beenden" unfolds the board with the
  next suggestion. Card position stays stable after the flight.
- Stapel: the piles slide down and fade, the server answered after about 150 ms, the card grows
  from 234 to 430 px until about 520 ms.
- Reduced motion: no card animation, columns switch instantly.
- Screens: `docs/screens/3.1-*`.

**Known issue (open question for Niels):** in the Stapel layout in a *desktop* browser with classic
scrollbars (a narrow desktop window), the page gets a scrollbar for about 400 ms during the fold;
the drawer wraps to two lines and the card jumps 20 px when the scrollbar goes. Phones use overlay
scrollbars, so this cannot happen there. Two fixes did not help (`overflow: clip` on the board,
wiping the tab bar with `clip-path`) and were reverted. Next idea: `scrollbar-gutter: stable` on the
shell page.
