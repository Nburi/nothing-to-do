## The flow

```
hourly app:run-planning-checks
  └ CrunchWatch::check → EarlyWarning (1.4: on at the first missing minute, hysteresis, notify hard only, once a day)
      notify → push pending
  └ CrunchWatch::pushIfDue → 08:00–21:00, not in a session, once a local day → push "Engpass am Mittwoch" → /board?crunch=1
board (board mode) → CrunchOverview (records the state as "seen": no push for what you already saw)
  └ line "Engpass bis Mittwoch: 2 Sessions fehlen · Ansehen"   (soft only: quiet "Weiche Fristen passen nicht ganz")
  └ session mode: a small "Engpass" in the rail / drawer (hard only)
Ansehen / push link → crunch screen (panel right / sheet bottom)
  └ Kleiner · Auf <+7 Tage> (soft) · Auf <Tag> … (hard and late: the first day it fits) or Verschieben … (hard: date + "Die Frist ist wirklich später") · Später
  └ Mehr Zeit: heute 17:30–19:30 (+4 Sessions) → one-off block via WeekPlanEditor::addOnce
  └ every decision: live recount, Rückgängig, board re-renders
```

## Decisions I made (please check)

- **Seen on the board = no push.** If the board (board mode) showed the warning first, the push is not sent. The push is for when you are not in the app. The crunch screen also counts as seen.
- **Push window 08:00–21:00 local**, checked hourly, so "right away" means within the next hour. At night it waits for the 08:00 run. One push a local day at most, a failed one is not retried that day.
- **Push copy:** „Engpass am Mittwoch“ (heute / morgen / weekday / date) and „2 Sessions fehlen bis «Bericht». Schau kurz drauf, du entscheidest.“ It names the hard task with the earliest deadline.
- **Board line names the last day that does not fit** („Engpass bis Donnerstag“); the push names the first overloaded day („am Mittwoch“). Usually the same day.
- **Missing time in sessions** (rounded up), minutes in brackets on the screen.
- **Which tasks are listed:** every open task with a deadline up to the last late deadline, because they compete for the same sessions. Soft ones are always the suggestion (outlined button), also when the engine kept them planned.
- **Soft "Verschieben" = +7 days in one tap** (like the slip rule G2); it resets the slip counter. Past the hard deadline the soft date is removed instead.
- **Hard "Verschieben"** needs a later date and the tick „Die Frist ist wirklich später“. Never by a rule. A late hard task shows „Auf Donnerstag …“ and its form starts with the first day it fits (see "Fitting date" below); any other hard task prefills the old date + 7 days.
- **"Mehr Zeit" suggestion:** first day from today until the last late deadline (at most 7 days) with room at 19:00, else right before or after one of its blocks, between 07:00 and 22:30, as long as the category's most common block (else 60 min), in a pomodoro category that takes the work's area. The form lets you change day (next 14 days), times and category.
- **During a session** only hard crunches show (a small „Engpass“ in the rail / drawer); soft ones stay quiet there.
- **Undo** keeps the last five decisions while the screen is open.

## Fitting date for a late hard deadline (2026-11-23, Niels' C24 finding)

Niels missed "move the deadline so that it fits". A late hard task now carries the first day its deadline
can move to so that the task fits, and the crunch screen proposes it. It is still only a proposal: the date
stays visible in the form, "Die Frist ist wirklich später" is still needed, "Abbrechen" changes nothing.
Soft first stays the default suggestion (the soft buttons are the outlined ones; the new button is neutral).

| Piece | What |
|---|---|
| `DeadlineFeasibility::fitDates()` | For every late hard task: `check()` again with that one hard deadline a day later each time (`PlannedTask::withHardDeadline`), the first day on which the task is not late. The planning engine does the counting (soft work gives way, area links, sessions that already started); there is no second capacity calculation. |
| `CrunchOverview::for(..., withFitDates: true)` | Fills `CrunchItem::fitDate` and `::late`. Only the crunch screen passes the flag. |
| `Crunch::startMove()` | Prefills the date with the proposal, else old date + 7 days as before. |
| Screen | Button „Auf Donnerstag …“ instead of „Verschieben …“; in the form „Ab Donnerstag passt «Bericht» in deinen Plan.“; with no day in the window the form says so („passt in den nächsten Wochen auf keinen Tag. Mehr Zeit oder eine kleinere Aufgabe helfen.“). |

Decisions I made (please check):

- **"Fits" = the task is not late and no other hard deadline that holds today is lost by the move.** Moving one deadline must not just move the crunch to another task (test: a date that only hands the crunch to another hard deadline is skipped). Soft work may still slip, that is the soft-first rule.
- **The search starts the day after the deadline** (after today when it is past, because a deadline only moves to a later day than today) and ends at the last day of the planning window (two weeks, longer when a deadline lies further out, at most 60 days). No day fits: no proposal, and the form says so.
- **Cost.** One engine run per late hard task and candidate day, so the board does not ask (the board line never needs the dates). Measured on a synthetic plan: 3 late hard tasks that fit nowhere cost 5 ms in a 14-day window, 22 ms in 30 days, 77 ms in 60 days; 10 such tasks in 60 days cost about 0.6 s. Only the crunch screen pays it. If it ever feels slow, look at stopping the scan early (check area links first).
