# Step 3.3 · Nudge at a fixed time per weekday

Refactor plan step 3.3 (R2; risks F1, C1, C2). Built 2026-11-16 on `feature/nudge-time`, stacked on
3.2 (`feature/battery-reset`, PR #19).

## Scope

Plan row 3.3: "Arrival trigger and Web Push. Uses the winner of spike 0.1; if the spike failed, ships the
time-based nudge only." Spike 0.1 is not tested on the iPhone yet (TESTBERICHT C2), so this step ships
**the time-based nudge only**. `POST /api/arrival` and the Wi-Fi path are untouched.

Niels' pick in the phase 3 preview (2026-11-11): the nudge comes at a **fixed time per weekday that you set**,
not "20 minutes before the first pomodoro block".

## The flow

```
Einstellungen › "Abschalten am Abend": one optional time per weekday (Mo–So)
At that time (local, DST-safe):
  push "Zeit zum Abschalten" → tap → /board?reset=1 → calm reset screen (3.2)
  and the first visit of the board from that time shows the reset by itself
No time on that weekday → no push, no offer by itself ("Abschalten" and the link still work)
Never set anything     → no push, offer from 17:00 as in 3.2
```

### The push rules (R2)

- **At most one per evening.** `evenings.nudge_sent_at` is claimed with an atomic `update … whereNull` before
  sending, so two overlapping scheduler runs cannot both send.
- **None on paused days** (week plan pauses), **none once tonight's reset was started or closed**, **none on a
  weekday without a time**, **none without a subscription** (no error, nothing written).
- **Not into a focus session.** While a pomodoro session (work or break) runs, the nudge waits; it goes out
  after the session if still within the catch-up window.
- **Catch-up window two hours.** A missed scheduler tick still sends on the next run; more than two hours
  late it stays quiet that evening (no push out of the blue at midnight).
- **Skipping is silent; nothing is counted.** Nothing reads `nudge_sent_at` beyond tonight.
- **Failures:** a failing push or a broken VAPID config is logged (`Evening nudge could not be sent`) and not
  retried tonight; the board still offers the reset from the nudge time. The notifier is built only when a
  nudge is due, so a server without VAPID keys runs the command without errors.
- **Time zone and DST (C2):** times are local wall-clock times, compared through `UserClock`, which uses the
  real IANA zone for Zurich / London / Helsinki. 18:00 stays 18:00 on both sides of the October and March
  changes. A time inside the March gap (02:00–03:00) fires at 03:00; the October repeat hour fires once.

## Decisions I made (please check)

- **Default for everyone: nothing set (`nudge_times = null`).** No user gets a push they did not ask for, and
  the reset keeps the 3.2 behaviour (offered from **17:00**). The card says so in its empty state.
- **Once you saved the card, a weekday without a time offers nothing by itself.** You left that day empty on
  purpose (weekends, for example), so the 17:00 fallback would contradict you. The push link and
  „Abschalten“ still work. A saved empty week behaves the same and the card says so.
- **The nudge time is also the "from" time for the reset offer.** One setting, not two.
- **Catch-up two hours**, then quiet (see above).
- **No push during a running pomodoro session** (work or break); it comes after, if still in the window.
- **Saving a time that has already passed today counts as tonight's nudge.** You are in the app right now; a
  push a minute later would only startle. The board offers the reset anyway.
- **A failed push is not retried that evening.** One try per evening, logged; avoids hammering a broken
  push service every minute.
- **"Zeit setzen" defaults** to the last time set above in the list, else 18:00.
- **Push copy:** „Zeit zum Abschalten“ / „Zehn Minuten nur für dich. Danach zeigt dir das Board, womit du
  anfängst.“ (the arrival spike keeps its own „Du bist zuhause“ copy).
- **Times are per calendar day.** A time after midnight (e.g. 00:30 on Tuesday) belongs to Tuesday's date.
- **No master on/off switch.** Removing all times is the off switch; the device's notification permission
  decides about the push.

## Later: arrival by location (2026-11-23, `feature/arrival-location`)

Niels tested spike 0.1 on 2026-11-17 (TESTBERICHT C2, guide `docs/spikes/0.1-arrival.md`): the Wi-Fi
automation is unreliable (after the train the hotspot was still on, the home Wi-Fi never connected, the
automation did not fire); the location automation ("Ankunft" at home) fired every time, about 60 seconds
before he enters the house. So location is the arrival trigger and `POST /api/arrival` now sends **the same
one nudge as the scheduler, only early**, under the same rules (it can fire again when he leaves and comes
back, or when he only passes by):

| Piece | What |
|---|---|
| `EveningNudge::holdOnArrival()` | The rules as a reason (`App\Services\Planning\NudgeHold`) or null: none on a weekday without a nudge time (also for a user who never saved the card), none once tonight's nudge went out, none once tonight's reset was started or closed, none on paused days, none during a focus session, none more than `ARRIVAL_EARLY_MINUTES` (2 h) before the nudge time. No end of the window. |
| `EveningNudge::claim()` | The atomic claim of `evenings.nudge_sent_at`, now one method for the scheduler, `save()` and the arrival. An arrival that loses the race to another arrival or to the scheduler sends nothing. `isDue()` shares the state checks with the arrival (`hold()`); its behaviour is unchanged. |
| `ArrivalController` | Held back: status 200, `sent: false`, a `reason` code and a German `message` for the Shortcut's "Ergebnis anzeigen", logged as `Arrival ping held back`. Pushed: `sent: true`, `devices`, `delivered`. No working push setup (no VAPID keys): 503 `push_unavailable`, the evening stays open. A push service that throws counts as sent (not retried tonight, like the scheduler). The push opens `/board?reset=1` (it was `/`, which shows no reset before the nudge time). |

### Decisions I made (please check)

- **An arrival is the nudge sent early, not an extra push.** One per evening, shared with the time-based nudge:
  whoever comes first sends it. So if the time-based nudge went out while you were still away, the arrival has
  nothing left to send. Set the weekday's time a bit later than your usual arrival and the arrival comes first.
- **No nudge time, no arrival push**, also for a user who never saved the card (like the scheduler: the card is
  the off switch). Before this change an arrival always pushed; the old spike test needed a nudge time now.
- **The window opens two hours before the nudge time** (`ARRIVAL_EARLY_MINUTES`), so a lunch visit or a trip
  past the house at noon cannot use up the evening. It has no end: coming home at 23:10 is a real signal.
- **A held-back arrival writes nothing**, so the time-based nudge still comes.
- **A missing push setup is not a failed push:** 503 and the evening stays open, so you can add the keys and
  arrive again the same evening. A failing push service is not retried tonight, as in the scheduler.
- **Several arrivals in one evening** (leaving and coming back, passing by) cannot be told apart from a real
  arrival. Only the first one counts. The location automation cannot do better; the answer says why a later
  one stayed silent.
