## `app:switch-preflight`

```
php artisan app:switch-preflight [--important-limit=10] [--no-counts] [-v]
```

Reads only (proof in the test: SQLite `PRAGMA query_only = ON` while it runs, and the table counts before and
after are equal). It works on the old production schema (every check first looks whether its table and columns
exist) and on the migrated one, so the same command runs before and after `migrate`.

| Level | Check | Exit code |
|---|---|---|
| BLOCK | A row whose foreign key points at nothing: `tasks` (user, area, project, group, stage, waits_on), `task_groups`, `group_notes`, `projects`, `project_stages`, `notes`, `areas`, `event_categories`, `category_area` (both sides), `schedule_events` (user, category), `craft_ideas`, `reminders` | 1 |
| BLOCK | A task pointing at an area, project or group of **another user** | 1 |
| WARN | Categories linked to a project, group or Agenda entry (D1) | 0 |
| WARN | Users with more than `--important-limit` open „Wichtig“ marks (D2) | 0 |
| NOTE | Groups with open tasks in several lists (each becomes a project, C32) | 0 |
| NOTE | Craft ideas not copied yet (C15); tasks still in the retired list `projects`; migrations not run yet | 0 |

Plus the row count of every table except the volatile ones (`sessions`, `cache`, `jobs`, …).

Deviation from the brief: `tasks` has no category column, so "tasks with a missing category" cannot exist. The
category checks are `schedule_events.category_id` and both sides of `category_area`.
Groups in several lists, category links and many „Wichtig“ marks are not BLOCK on purpose: the migration handles
the first, and the other two are decisions, not damage. An orphan needs a foreign key that is missing or not
enforced (SQLite by default, or a column without a constraint); an enforced one on MariaDB/MySQL refuses it.

Tests: `tests/Feature/Commands/SwitchPreflightTest.php` (12).
