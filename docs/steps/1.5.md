# Step 1.5 · Capture endpoint and API parity

Refactor plan step 1.5 (R3; risks C10, C12). Built 2026-11-08, stacked on 1.2 (PR #11). No UI: the capture
line and the daily sort are step 2.3.

## What changed

| Piece | What |
|---|---|
| `App\Services\Planning\Capture` | One line into the Inbox. Trims, collapses whitespace (dictation), up to 500 characters, at the end of the Inbox. German messages. Every entry point uses it. |
| `POST /api/capture` | `{ "text": "…" }` → 201 `{ id, title, list, message }`. Needs a token with `capture:inbox` (or a full token). 30 per minute. |
| `NarrowAbility::CAPTURE`, `app:capture-token {email}` | The narrow token for the Shortcut. It can call `/api/capture` and nothing else (RejectNarrowTokens), revocable in Settings. |
| REST parity | `GET /suggestion`, `POST /suggestion/another`, `PUT /evening/battery`, `GET /session`, `POST /session/{start,done,pause,resume,stop}`, `GET /forecast`, `POST /tasks/{id}/drop`, `POST /tasks/{id}/shrink`, `/areas` (CRUD), `area_ids` on event categories. |
| Task fields | `size`, `hard_deadline`, `soft_deadline`, `soft_slips` (read only), `area_id`, `first_step` and list `later` in `TaskResource`, REST and MCP (`TaskMutator::applyRefactorFields`). Titles up to 500 characters. |
| MCP | New tools `get_suggestion`, `change_suggestion` (another, battery), `get_session`, `control_session`, `get_forecast`; `create_task` / `update_task` take the new fields. Write tools need `mcp:write`. |
| `PlanningPayload` | One JSON shape for suggestion, session and forecast, shared by REST and MCP. |
| `config/app.php` | **Default locale `de`** (G6). `.env.example` too. |
| `/docs/api` | New section "Erfassen und Planung"; Shortcut ① now uses `/capture`. `/docs/mcp` lists the new tools by itself. |

## Pruned (C12)

Nothing in the API or MCP still pointed at the features removed before the refactor (Agenda, Vorbereiten,
Projekte, Gruppen, Notfallmodus); `remove-old-features` had already taken them out. One stale comment about
`group_id` in `ListTasksTool` is fixed. The old per-event focus timer endpoints (`/schedule-events/{id}/…-focus`)
stay: the old screens still use them; they go with the old screens (risk C11).

## Decisions I made (please check)

- **Capture up to 500 characters** (the quality bar asks for 400 to work).
- **Default locale German** in config. The dev server's `.env` already says `APP_LOCALE=de`; prod should too.
  Without German validation files Laravel falls back to English for generic messages, so the old screens do not change.
- **A full API token may capture**, so an existing Shortcut can switch to `/capture` without a new token.
- **The capture token is created with a command**, like the arrival token. A settings screen comes with 2.3.
