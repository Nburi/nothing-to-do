# Step 4.6 · „Wichtig" marker

Refactor plan step 4.6 (R5, R7; risk F5). Built 2026-11-23 on `feature/important-marker`, based on step 3.4
(PR #21) and on the docs change in PR #27 (R5 keeps „Wichtig" as the only priority; plan question Q3).
**No migration:** `tasks.is_important` from the old app is the marker; the column and the production data stay
as they are.

## The order

What comes next, best first:

1. Work that is late or has to start today (as before).
2. Deadline work: the earliest binding date first; on the same date hard before soft; on the same date and kind
   the marked task first.
3. „Wichtig" without a deadline, as its own tier.
4. Everything else.

Inside each group the battery rule still orders (Okay: smaller first; Low: a warm-up of up to two Quick tasks, then
smaller first, big work shrunk to one session; Good: bigger first), then the user's board order, then the id. So
„Wichtig" never jumps a deadline, and it beats the battery and the size between undated tasks. A marked task that
has a deadline keeps its deadline reason; an undated one says it was marked. Outside pomodoro blocks nothing is
suggested, marked or not (R9, section 3 item 7).

`ImportantOrderTest` holds the three levels, the ties (same deadline, two marked tasks, same board place, input
order) and the battery cases. Seven of its tests are guards for rules that already held, so a later change cannot let
„Wichtig" jump a deadline.

## Where it shows

- **At the top of its list.** Marked tasks first, the rest in the user's order (`sort_order` is not touched), in the
  Werkbank columns, the Stapel sheet and as the top card of a pile.
- **Where the app offers no work suggestion** (outside pomodoro blocks): a "Wichtig" card under the start card (or
  the free-time idea) lists up to three marked tasks and "+ N weitere". It is no "Start here" card; Start on a row
  works as a manual start. While a work block runs there is no reminder: the marked task is ranked first and sits at
  the top of its list anyway.
- **While the board is folded:** the rail (Werkbank) and the drawer (Stapel) show "Wichtig n" and open the new tab.
  The tab also holds the toggle, so a task can be marked or unmarked during a session.
- **Not colour alone:** a solid flag against an outline flag, the word "Wichtig", and a thicker edge.

## Decisions I made (please check)

- **The marker works on every open item in every list**, so a marked item can always be unmarked where it shows.
  The reminder and the tab list **Inbox, To-dos and Tasks, not Later**: Later is parked on purpose (R6), and a task
  dropped there by a crunch decision keeps its mark in its list without nagging.
- **One gesture is one tap on the flag.** The new shell has no swipe on rows yet; adding one is a separate step.
- **The session card has no flag.** Its geometry is matched by the fold's ghost card (C1 fix); a changed card would
  make marked tasks jump. Marking during a session goes through the peek panel and the sheet.
- **Between undated tasks the battery rule still applies** inside the marked group (smaller first on an Okay evening)
  before the board order. R5 says „Wichtig" → board order; the engine's size and battery rule between them is older
  and unchanged. Say if marked tasks should go in board order only.
- **The crunch decisions (4.2) do not know „Wichtig".** A marked task can still be offered for shrink or drop.
  Not part of this step; see the question below.

## Open question for Niels: „Bis wann?"

Should marking a task **without a date** offer an optional „Bis wann?" (plan row 4.6)? Not built, as agreed.
**Recommendation: yes, but quiet.** After the tap that marks an undated task, show one inline line under the row
("Bis wann? Heute · Morgen · Diese Woche · Später"), skippable by ignoring it, never a dialog and never blocking the
one-tap mark. It writes the **soft** deadline (a hard one is a commitment the user has to choose deliberately). Why:
the stated use is "due tomorrow, bad consequences", and a date lets the deadline tiers, the capacity forecast and the
early warning see the task; without it „Wichtig" only reorders. Risk: if everything gets a date the marker stops
meaning "no date, still urgent", so the offer must stay easy to ignore and never repeat for the same task.

## Existing data

marked tasks, which would flood the reminder. TESTBERICHT C45 asks Niels to count them on the production copy; if some
users have many, decide in step 5.4 whether to clear the marks at the switch.
